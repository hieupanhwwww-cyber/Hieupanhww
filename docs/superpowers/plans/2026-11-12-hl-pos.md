# HL POS – Kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App bán hàng kiểu KiotViet cho Nội Thất Hùng Loan: bán lẻ + in hóa đơn, hàng hóa/kho, đơn nội thất, báo cáo; 2 vai trò chủ/nhân viên.

**Architecture:** Mọi quy tắc nghiệp vụ và phân quyền nằm trong Postgres (Supabase): bảng có RLS, thao tác ghi quan trọng đi qua hàm RPC chạy trong một giao dịch. Giá vốn nằm ở bảng riêng chỉ chủ đọc được. Giao diện Next.js (App Router, client components) gọi Supabase trực tiếp; chỉ việc tạo tài khoản nhân viên đi qua route server dùng service role key.

**Tech Stack:** Next.js 16 + React + Tailwind 4, @supabase/supabase-js + @supabase/ssr, Vitest, `pg` (test SQL trên Postgres 16 cục bộ), exceljs (xuất Excel), html-to-image (ảnh hóa đơn gửi Zalo).

**Spec:** `docs/superpowers/specs/2026-11-12-hl-pos-design.md`

## Global Constraints

- Tiền lưu bằng số nguyên đồng (`bigint`), không số thực.
- Báo cáo tính từ hóa đơn và đơn, không lưu bảng tổng riêng.
- Tồn kho = tổng các phiếu kho (nhập +, xuất −), không có cột tồn sửa tay.
- Nhân viên không đọc được giá vốn, lợi nhuận: chặn ở DB (RLS/hàm kiểm tra vai trò).
- Bán hàng + trừ kho trong một giao dịch duy nhất.
- Chỉ 2 vai trò: `owner`, `staff`.
- In hóa đơn khổ A5 qua trình duyệt.
- Giao diện tiếng Việt, tông trắng – sữa – nâu, dùng được trên điện thoại.
- Không thêm tính năng ngoài spec (không quét mã vạch, không offline, không công nợ khách riêng, không in 80mm).

### Task 3: Hàng hóa + phiếu kho (DB) + màn Hàng hóa

**Interfaces – Produces:**
- `products(id uuid pk, code text unique not null, name text not null, kind text check in ('goods','material'), unit text, sale_price bigint ≥0, low_stock_threshold numeric ≥0 default 0, active bool default true, created_at)`.
